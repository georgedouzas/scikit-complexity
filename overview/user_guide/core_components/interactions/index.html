    Interactions

    An interaction changes the states of elements. It binds elements through roles, such as target and source, reads their states, and returns laws, the equations or rules that a solver runs. It holds no state of its own. An element holds the states, a space says which members neighbour each other, and a system composes elements, interactions, and a space into one model. How the parts fit shows the families together, and the interactions parts page compares every interaction class and holds its fact sheet.

    Interaction

    An Interaction is the base of an interaction class of your own. The class declares each role and parameter as an argument of its __init__, annotated with RoleSpec or ParameterSpec, and returns its laws from _get_laws. Here susceptible people become infected at a rate proportional to the product of the two compartments, the mass action of epidemiology.

    from typing import Annotated

from skcomplex.core.components.elements import Element
from skcomplex.core.components.interactions import Interaction
from skcomplex.core.components.laws import RateLaw
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.specs import ParameterSpec, RoleSpec, StateSpec


class AmountElement(Element):
    def __init__(self, label, visual=None, *, x: Annotated[float, StateSpec()] = 0.0):
        super().__init__(label, visual=visual)
        self.x = x


class ConversionInteraction(Interaction):
    law_classes = (RateLaw,)

    def __init__(
        self,
        label,
        *,
        target: Annotated[str, RoleSpec()],
        source: Annotated[str, RoleSpec()],
        a: Annotated[float, ParameterSpec()] = 0.01,
    ):
        super().__init__(label)
        self.target = target
        self.source = source
        self.a = a

    def _get_laws(self, namespace):
        flow = namespace.a * namespace.target.x * namespace.source.x
        return [RateLaw(namespace.target.x, -flow), RateLaw(namespace.source.x, flow)]


people = [AmountElement('susceptible', x=99.0), AmountElement('infected', x=1.0)]
infection = ConversionInteraction('infection', target='susceptible', source='infected', a=0.01)
epidemic = CompositeSystem(elements=people, interactions=[infection])
simulate(epidemic, until=10, dt=5.0).get_values('infected.x').round(1).tolist()

    [1.0, 60.0, 99.6]

    The infected grow from 1 to 60.0 after five days and to 99.6 after ten. This is the logistic curve of a simple epidemic, in which every person ends infected.

    The same class describes autocatalysis in chemistry, where a molecule of B turns a molecule of A into a second B, as in the reaction A + B -> 2B.

    species = [AmountElement('A', x=2.0), AmountElement('B', x=0.1)]
autocatalysis = ConversionInteraction('autocatalysis', target='A', source='B', a=1.0)
reactor = CompositeSystem(elements=species, interactions=[autocatalysis])
simulate(reactor, until=4, dt=2.0).get_values('B.x').round(3).tolist()

    [0.1, 1.615, 2.091]

    The concentration of B rises from 0.1 to 1.615 and then to 2.091, close to the total of 2.1 that the reaction conserves.

    How the engine runs it. prepare reads the annotations to find the roles and parameters. At compile time the interaction returns its laws for a namespace whose attribute target holds the symbols of the states of the element that role binds, and whose attribute a is the symbol of the parameter. The class attribute law_classes names the kinds of its laws, so get_tags knows them before a run. Rate laws on one state add up, and the system of ordinary differential equations goes to ScipyODESolver.

    sorted(infection.get_tags().laws), sorted(infection.get_requirements().roles)

    (['rate'], ['source', 'target'])

    The interaction emits rate laws and binds the roles source and target.

    How it combines. A role binds an element, a group, or a member of a group. When it binds a group, the laws run once for every member of the group, as arrays. An interaction of this kind sits beside the others of a system, and its laws add to the rates they give to the same state.

    Limits and errors. The laws run once per bound element or member, so an interaction that runs along the edges of a network or between close members derives from NeighborInteraction or PairInteraction. Every role must name an element or a group of the system, and simulate raises a RoleError otherwise.

    from skcomplex.core.errors import RoleError

wrong = ConversionInteraction('infection', target='susceptible', source='sick')
try:
    simulate(CompositeSystem(elements=people, interactions=[wrong]), until=1)
except RoleError as error:
    message = str(error)
message

    The system is not valid, with 1 error(s):
- infection: Interaction infection binds the role 'source' to 'sick', which is not an element or group path relative to the root system. Bind every role to the path of an element, group, or member of the system. [role]

    The message says that the role source is bound to 'sick', which is not the path of an element or a group. The fix is the path 'infected'.

    A field realization. A field names the roles in its own words, such as foxes that eat rabbits and turn a part of them into new foxes.

    class PredationInteraction(Interaction):
    law_classes = (RateLaw,)

    def __init__(
        self,
        label,
        *,
        prey: Annotated[str, RoleSpec()],
        predator: Annotated[str, RoleSpec()],
        a: Annotated[float, ParameterSpec()] = 0.02,
        b: Annotated[float, ParameterSpec()] = 0.01,
    ):
        super().__init__(label)
        self.prey = prey
        self.predator = predator
        self.a = a
        self.b = b

    def _get_laws(self, namespace):
        meetings = namespace.prey.x * namespace.predator.x
        return [
            RateLaw(namespace.prey.x, -namespace.a * meetings),
            RateLaw(namespace.predator.x, namespace.b * meetings),
        ]


PredationInteraction('hunting', prey='rabbits', predator='foxes').get_params()

    {'a': 0.02, 'b': 0.01, 'label': 'hunting', 'predator': 'foxes', 'prey': 'rabbits'}

    RateInteraction

    A RateInteraction adds a rate, and optionally a noise, to the time derivative of one state, so it needs no class of its own. Here a capacitor of time constant 2 seconds charges through a resistor toward a source of 5 volts.

    from typing import Annotated

from skcomplex.core.components.elements import Element
from skcomplex.core.components.interactions import RateInteraction
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.specs import StateSpec


class AmountElement(Element):
    def __init__(self, label, visual=None, *, x: Annotated[float, StateSpec()] = 0.0):
        super().__init__(label, visual=visual)
        self.x = x


charging = RateInteraction('charging', target='capacitor', rate=lambda s: (5.0 - s.target.x) / 2.0)
circuit = CompositeSystem(elements=[AmountElement('capacitor')], interactions=[charging])
simulate(circuit, until=4, dt=2.0).get_values('capacitor.x').round(2).tolist()

    [0.0, 3.16, 4.32]

    The voltage reaches 3.16 after 2 seconds and 4.32 after 4, which is 5 (1 - exp(-t / 2)).

    The same class with a noise gives the geometric Brownian motion of a stock price, with a drift of 5 percent and a volatility of 20 percent a year. A noise is a random term noise(namespace) dW, where dW is the increment of a Wiener process, the random walk of continuous time.

    price = RateInteraction('price', target='stock', rate=lambda s: 0.05 * s.target.x, noise=lambda s: 0.2 * s.target.x)
market = CompositeSystem(elements=[AmountElement('stock', x=100.0)], interactions=[price])
round(float(simulate(market, until=1, dt=1.0, random_state=0).get_values('stock.x')[-1]), 1)

    126.2

    The price ends the year at 126.2 in this run. Another seed draws another path, and a study averages many of them.

    How the engine runs it. The interaction returns a rate law, and a noise law when it has a noise. Without noise the laws form ordinary differential equations, which ScipyODESolver integrates. With noise they form stochastic differential equations, which EulerMaruyamaSolver integrates. On a state of order 2 the rate adds to the second derivative, so it acts as an acceleration.

    sorted(charging.get_tags().laws), sorted(price.get_tags().laws)

    (['rate'], ['noise', 'rate'])

    The first interaction emits a rate law, and the second a rate law and a noise law.

    How it combines. The role target binds an element or a group, and sources names the elements the rate reads without changing them. Rates on one state add, so a birth rate and a death rate can be two interactions. A divisor, such as a capacitance or a mass, divides the rate and the noise.

    Limits and errors. A rate reads the target and the sources only, with no neighbours, so a coupling between members of a group needs CouplingInteraction or NeighborInteraction. The stochastic calculus of the noise must be 'ito', 'stratonovich', or 'anti-ito', and prepare raises a ValidationError for any other name.

    from skcomplex.core.errors import ValidationError

try:
    RateInteraction('price', target='stock', noise=0.2, convention='itoh').prepare()
except ValidationError as error:
    message = str(error)
message

    Unknown noise convention 'itoh'. Use one of ito, stratonovich, anti-ito.

    The message reads "Unknown noise convention 'itoh'. Use one of ito, stratonovich, anti-ito." The fix is convention='ito', the default.

    A field realization. A field fixes the rate and names its parameter, such as the recovery of infected people at a rate gamma. The rate reads the parameter from the namespace, so set_params changes it.

    from skcomplex.core.specs import ParameterSpec


class RecoveryInteraction(RateInteraction):

        super().__init__(label, target=target, rate=lambda s: -s.gamma * s.target.x)
        self.gamma = gamma


recovery = RecoveryInteraction('recovery', target='infected', gamma=0.2)
ward = CompositeSystem(elements=[AmountElement('infected', x=100.0)], interactions=[recovery])
simulate(ward, until=5, dt=5.0).get_values('infected.x').round(1).tolist()

    [100.0, 36.8]

    The infected fall from 100 to 36.8 in five days, which is 100 exp(-0.2 t).

    See its fact sheet and its API entry.

    TransferInteraction

    A TransferInteraction moves an amount out of a state of one holder and into a state of another, so what one loses the other gains. Here a tenant pays a rent of 100 a month to a landlord.

    from typing import Annotated

from skcomplex.core.components.elements import Element
from skcomplex.core.components.interactions import TransferInteraction
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.specs import StateSpec


class AccountElement(Element):
    def __init__(self, label, visual=None, *, cash: Annotated[float, StateSpec()] = 0.0):
        super().__init__(label, visual=visual)
        self.cash = cash


rent = TransferInteraction('rent', source='tenant', target='landlord', state='cash', amount=100.0)
accounts = [AccountElement('tenant', cash=500.0), AccountElement('landlord')]
trajectory = simulate(CompositeSystem(elements=accounts, interactions=[rent]), until=3, dt=1.0)
trajectory.get_values('tenant.cash').round(1).tolist(), trajectory.get_values('landlord.cash').round(1).tolist()

    ([500.0, 400.0, 300.0, 200.0], [0.0, 100.0, 200.0, 300.0])

    The tenant falls from 500 to 200 in three months, and the landlord rises from 0 to 300.

    The same class lets water flow from an upper reservoir into a lower one, at a rate of half the upper level.

    class ReservoirElement(Element):
    def __init__(self, label, visual=None, *, level: Annotated[float, StateSpec()] = 0.0):
        super().__init__(label, visual=visual)
        self.level = level


half = lambda s: s.source.level / 2
outflow = TransferInteraction('outflow', source='upper', target='lower', state='level', amount=half)
reservoirs = [ReservoirElement('upper', level=4.0), ReservoirElement('lower')]
trajectory = simulate(CompositeSystem(elements=reservoirs, interactions=[outflow]), until=2, dt=2.0)
trajectory.get_values('upper.level').round(3).tolist(), trajectory.get_values('lower.level').round(3).tolist()

    ([4.0, 1.472], [0.0, 2.528])

    After two hours the upper level falls to 1.472, which is 4 exp(-1), and the lower rises to 2.528, so their sum stays 4.

    How the engine runs it. In its symbolic form the interaction returns one transfer law per leg. A transfer law is one outflow of the source and one inflow of the target, and its amount is a rate in continuous time. The trajectory records each flow under its name, such as rent.flow_0.

    trajectory.names

    ['upper.level', 'lower.level', 'outflow.flow_0']

    The names hold the two levels and the flow outflow.flow_0.

    How it combines. The roles source and target bind two elements or two groups, or one holder twice for a transfer between its own states, such as susceptible to infected. legs move further amounts in the same event, and Source() and Sink() stand for the environment outside the system. With a rate, the amount moves in random jumps. In the agent form, pairing pairs the members of two groups, as in a market.

    Limits and errors. A transfer conserves the amount it moves, so a quantity that is created or destroyed needs a leg from Source() or into Sink(), or a RateInteraction. The form must be 'symbolic' or 'agent', and prepare raises a ValidationError for any other name.

    JumpInteraction

    A JumpInteraction is a random event that changes states by whole amounts. Here births and deaths change a population of 20 one animal at a time, at rates of 0.5 and 0.4 per animal a year.

    from typing import Annotated

from skcomplex.core.components.elements import Element
from skcomplex.core.components.interactions import JumpInteraction
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.specs import StateSpec


class AmountElement(Element):
    def __init__(self, label, visual=None, *, x: Annotated[float, StateSpec()] = 0.0):
        super().__init__(label, visual=visual)
        self.x = x


births = JumpInteraction('births', target='population', changes={'x': 1}, rate=lambda s: 0.5 * s.target.x)
deaths = JumpInteraction('deaths', target='population', changes={'x': -1}, rate=lambda s: 0.4 * s.target.x)
population = CompositeSystem(elements=[AmountElement('population', x=20.0)], interactions=[births, deaths])
simulate(population, until=10, dt=5.0, random_state=0).get_values('population.x').tolist()

    [20.0, 17.0, 13.0]

    The population falls to 17 after five years and to 13 after ten in this run. Its mean grows as 20 exp(0.1 t), but a small population can drift down, and another seed draws another path.

    The same class describes customers who join a queue twice a minute and each leave after one minute on average.

    join = JumpInteraction('join', target='queue', changes={'x': 1}, rate=lambda s: 2.0)
leave = JumpInteraction('leave', target='queue', changes={'x': -1}, rate=lambda s: s.target.x)
shop = CompositeSystem(elements=[AmountElement('queue')], interactions=[join, leave])
lengths = simulate(shop, until=200, dt=1.0, random_state=0).get_values('queue.x')
bool((lengths >= 0).all()), round(float(lengths.mean()), 1)

    (True, 1.9)

    The length never falls below 0, and its mean over 200 minutes is 1.9, close to the value 2 of queueing theory.

    How the engine runs it. The interaction returns a jump law, whose propensity is the rate. GillespieSolver runs the stochastic simulation algorithm of Gillespie: it draws the time of the next event from the total propensity, picks the event in proportion to its propensity, and applies its changes.

    sorted(join.get_tags().laws)

    ['jump']

    The interaction emits a jump law.

    How it combines. The role target binds an element or a group. Several jump interactions on one target form one jump process. With probability in place of rate the event fires once per step of discrete time, and with waiting it fires after a drawn waiting time, as in a renewal process.

    Limits and errors. The changes are fixed amounts, so a change that depends on the states needs a MapInteraction or a TransitionInteraction. An event has exactly one clock, and prepare raises a ValidationError for none or several.

    from skcomplex.core.errors import ValidationError

try:
    JumpInteraction('join', target='queue', changes={'x': 1}, rate=lambda s: 2.0, probability=lambda s: 0.1).prepare()
except ValidationError as error:
    message = str(error)
message

    The jump 'join' has the clocks ['rate', 'probability']. Give exactly one of rate, probability, waiting.

    The message says that the jump join has the clocks rate and probability. The fix is one of them.

    A field realization. A field fixes the change and names the rate, such as births at a rate b per individual.

        self.b = b

    MapInteraction

    A MapInteraction sets the next value of a state at every step of discrete time. Here the logistic map follows a population, as a fraction of its carrying capacity, from one year to the next.

    from typing import Annotated

from skcomplex.core.components.elements import Element
from skcomplex.core.components.interactions import MapInteraction
from skcomplex.core.components.spaces import DiscreteTime
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.specs import StateSpec


class AmountElement(Element):
    def __init__(self, label, visual=None, *, x: Annotated[float, StateSpec()] = 0.0):
        super().__init__(label, visual=visual)
        self.x = x


logistic = lambda s: 2.5 * s.target.x * (1 - s.target.x)
growth = MapInteraction('growth', target='population', state='x', function=logistic)
census = CompositeSystem(elements=[AmountElement('population', x=0.1)], interactions=[growth], time=DiscreteTime())
simulate(census, until=3).get_values('population.x').round(4).tolist()

    [0.1, 0.225, 0.4359, 0.6147]

    The fraction goes from 0.1 to 0.225, 0.4359, and 0.6147, on its way to the fixed point 0.6 of the map.

    The same class compounds the interest of a bank account once a month. With mode='increment' the function gives the change, not the next value.

    monthly = lambda s: 0.01 * s.target.x
interest = MapInteraction('interest', target='account', state='x', function=monthly, mode='increment')
bank = CompositeSystem(elements=[AmountElement('account', x=1000.0)], interactions=[interest], time=DiscreteTime())

    1126.83

    After twelve months at 1 percent a month the balance is 1126.83, which is 1000 * 1.01 ** 12.

    How the engine runs it. The symbolic form returns update laws, and IterationSolver applies them once per step. The members of a group update all at once by default, from the states at the start of the step. The schedule 'sequential' or 'random-sequential' updates them one after another. In the agent form, with form='agent', the function takes the agent and a view of the system and returns its next value.

    sorted(interest.get_tags().laws)

    ['update']

    The interaction emits an update law, the next value of a state.

    How it combines. The role target binds an element or a group, and sources names the elements or members the function reads. Maps on different states of one system run in the same step, and the maps of the agent form run in phases of the step.

    Limits and errors. A map gives the next value in discrete time, so a state that flows needs a RateInteraction. The function must be callable, and prepare raises a ValidationError otherwise.

    from skcomplex.core.errors import ValidationError

    MapInteraction('interest', target='account', state='x', function=0.01, mode='increment').prepare()
except ValidationError as error:
    message = str(error)

    SamplingInteraction

    A SamplingInteraction samples the states of the members by Monte Carlo moves. Every sweep proposes a new value for each member and accepts it with a probability that depends on the change of an objective, such as an energy, scaled by intensity, the inverse of a temperature. Here the spins of a magnet in the Ising model align on a lattice of 8 by 8 sites from a random start.

    ConnectionInteraction

    A ConnectionInteraction joins the ports of elements at a node, so that their potentials agree and their flows sum to zero. A port is a named connector of an element, such as a pin of a resistor, with a potential and a flow.     ports: ClassVar = {'a': PIN}
    law_classes = (EquationLaw,)

    def __init__(
        self,
        label,

        *,

        a_i: Annotated[float, StateSpec(algebraic=True)] = 0.0,

        self.a_i = a_i

    TrainingInteraction

    A TrainingInteraction fits the parameters of a nested system to data by gradient steps, as a neural network is trained. The nested system runs through the data in its own time, and every step of the outer system is one epoch of training. Here a model of a drug in the blood, which keeps a fraction a of the drug each hour, learns a from a series of concentrations that fall to 0.8 of their value each hour.

    from typing import Annotated

import numpy as np

from skcomplex.core.components.elements import Element

from skcomplex.core.components.spaces import DiscreteTime

from skcomplex.core.specs import DatasetSpec, ObservableSpec, ParameterSpec, StateSpec


class FactorElement(Element):
    def __init__(
        self,
        label,
        visual=None,
        *,
        x: Annotated[float, StateSpec()] = 1.0,
        a: Annotated[float, ParameterSpec(adaptive=True)] = 0.5,
        observed: Annotated[float, ParameterSpec()] = 0.0,
    ):
        super().__init__(label, visual=visual)
        self.x = x
        self.a = a
        self.observed = observed

    def _get_laws(self, namespace):
        return [UpdateLaw(namespace.x, namespace.a * namespace.x)]

    'fit',
    system='blood',
    trained=['unit.a'],
    loss=squared_error,

    learning_rate=0.05,
    batch_size=1,
)
