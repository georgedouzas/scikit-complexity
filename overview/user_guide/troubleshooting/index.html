    Troubleshooting

    This page lists every error of skcomplex.core.errors, with the shortest code that raises it, its message, what it means, and the fix. Search the page for the name of the error a run raised. Each class is a subclass of SkcomplexError, and most checks of a system raise a subclass of ValidationError.

    simulate checks a whole system before it compiles and raises one error that lists every problem it found. Each line of that message names the path of the part, the problem, a fix, and a short code in brackets, such as [role]. The error takes the class of its problems when they share one, and is a ValidationError when they differ.

    Each section runs on its own. Most use a population of hares that grows at the rate 0.55 a year, or the hare and lynx model of the build tutorial with the rates of Carpenter (2018).

    SkcomplexError

    Every error of the library subclasses SkcomplexError, so one except clause catches them all. Here a solver for maps meets a system of rates.

    from skcomplex.core.engine.runtime import simulate
from skcomplex.core.engine.solvers import IterationSolver
from skcomplex.core.errors import SkcomplexError
from skcomplex.systems.biology.ecology import LotkaVolterraSystem

system = LotkaVolterraSystem(prey=30.0, predators=4.0, r=0.55, a=0.028, b=0.024, d=0.80)
try:
    simulate(system, until=20, solver=IterationSolver())
except SkcomplexError as error:
    name, message = type(error).__name__, str(error)
name, message

    ('TagError',
 'The solver IterationSolver does not support the time continuous of the system. Pass a solver that supports them, '
 'or none for the default.')

    The error is a TagError, one of the subclasses below. Catch the root class where a program treats every error of the library the same way, such as a sweep that logs failed runs and goes on. Catch a subclass where the fix depends on the error. A few checks keep the errors of Python and scikit-learn, such as the ValueError of set_params for an unknown name and the KeyError of get_values for a missing path.

    NotPreparedError

    A part runs only after prepare has checked it. A law run on its own before it is prepared raises this error.

    from sage.all__sagemath_symbolics import var

from skcomplex.core.components.laws import RateLaw
from skcomplex.core.errors import NotPreparedError

x = var('x')
try:
    RateLaw(x, 0.5 * x).run({'x': 10.0})
except NotPreparedError as error:
    message = str(error)
message, RateLaw(x, 0.5 * x).prepare('growth').run({'x': 10.0}).value_

    ('RateLaw must be prepared before it runs. Call `prepare(...)` first.', 5.0)

    The message reads "RateLaw must be prepared before it runs. Call prepare(...) first." The fix calls prepare first, and the rate at x = 10 is then 5.0. simulate prepares every part of a system itself, so a run never meets this error.

    ValidationError

    A value that breaks a rule of its part or of the run raises a ValidationError, the parent of most errors below. Here the initial state names the hares by the label of the build tutorial, while the catalog class calls them prey.

    from skcomplex.core.engine.runtime import simulate
from skcomplex.core.errors import ValidationError
from skcomplex.systems.biology.ecology import LotkaVolterraSystem

try:
    simulate(system, until=20, initial_state={'hares.x': 10.0})
except ValidationError as error:
    message = str(error)
message, simulate(system, until=1, dt=1.0, initial_state={'prey.x': 10.0}).get_values('prey.x').round(1).tolist()

    ('The initial state names hares.x, which are not states of the system. Use the dotted names of states, such as '
 'prey.x, predators.x.',
 [10.0, 15.9])

    The message says that hares.x is not a state of the system and suggests prey.x and predators.x. With prey.x the run starts from 10.0 thousand hares and reaches 15.9 thousand after a year.

    ContextError

    Some objects prepare against an owner, such as a solver against the problem it advances. Prepared alone, without that context, they raise this error.

    from skcomplex.core.engine.runtime import simulate

    message = str(error)
message, simulate(system, until=2, dt=1.0, solver=RK4Solver()).get_values('prey.x').round(1).tolist()

    ('A solver prepares on a compiled problem. Pass the problem to `prepare`.', [30.0, 46.4, 68.5])

    The message reads "A solver prepares on a compiled problem. Pass the problem to prepare." The fix passes the solver to simulate, which compiles the problem and prepares the solver on it. The run gives 30.0, 46.4, and 68.5 thousand hares.

    AlgebraicStateError

    An algebraic state has no derivative of its own. The equations of its system fix its value at every time, so a rate law on it has no meaning.

    from typing import Annotated

from skcomplex.core.components.elements import Element
from skcomplex.core.components.laws import RateLaw
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.errors import AlgebraicStateError
from skcomplex.core.specs import StateSpec


class LevelElement(Element):
    def __init__(self, label, *, x: Annotated[float, StateSpec(algebraic=True)] = 0.0):
        super().__init__(label)
        self.x = x

    def _get_laws(self, namespace):
        return [RateLaw(namespace.x, 1.0)]


try:
    simulate(CompositeSystem(elements=[LevelElement('level')]), until=1)
except AlgebraicStateError as error:
    message = str(error)
message.splitlines()[-1]

    - level: The RateLaw of level targets the algebraic state level.x, but the equations of the system determine this state. State the value of level.x with an `EquationLaw`, or declare it as a state of order 1. [algebraic-law]

    The code is algebraic-law. The message says that the RateLaw of level targets the algebraic state level.x, and suggests an EquationLaw for its value or a state of order 1. The fix below states the value with an equation.

    from skcomplex.core.components.laws import EquationLaw

    def _get_laws(self, namespace):
        return [EquationLaw(namespace.x, 2.0)]


simulate(CompositeSystem(elements=[FixedLevelElement('level')]), until=1, dt=1.0).get_values('level.x').tolist()

    [2.0, 2.0]

    The level holds 2.0 at both frames.

    ConservationError

    A run checks the invariants it is given at every frame, and a quantity that drifts further than its tolerance raises this error. The Lotka and Volterra model keeps V = b H - d ln H + a L - r ln L constant along every orbit, and forward Euler drifts off it.

    import numpy as np

from skcomplex.core.engine.runtime import simulate
from skcomplex.core.engine.solvers import EulerSolver
from skcomplex.core.errors import ConservationError
from skcomplex.core.specs import ObservableSpec
from skcomplex.systems.biology.ecology import LotkaVolterraSystem

system = LotkaVolterraSystem(prey=30.0, predators=4.0, r=0.55, a=0.028, b=0.024, d=0.80)


def get_constant(t, values):
    prey, predators = values['prey.x'], values['predators.x']
    return 0.024 * prey - 0.80 * np.log(prey) + 0.028 * predators - 0.55 * np.log(predators)


constant = ObservableSpec('constant', function=get_constant)
try:
    simulate(
        system, until=20, dt=1.0, solver=EulerSolver(dt=0.1), observables=[constant], invariants={'constant': 1e-3}
    )
except ConservationError as error:
    message = str(error)
message

    The invariant constant changed from -2.65142 to -2.64349 at frame 1, time 1, beyond its tolerance 0.001.

    The message says that the invariant changed from -2.65142 to -2.64349 at frame 1, beyond its tolerance 0.001. The fix is a smaller step, a solver of higher order such as RK4Solver, or the default solver, which keeps the constant.

    TensorShapeError

    The operations on tensors read matrices and vectors of expressions. A value of another shape raises this error.

    from sage.all__sagemath_symbolics import SR, identity_matrix, var

from skcomplex.core.components.laws.utils import tensor_divergence
from skcomplex.core.errors import TensorShapeError

try:

    message = str(error)

    ('tensor_divergence needs a square matrix, but got p, which has another shape.', (partial(p, 0), partial(p, 1)))

    The message reads "tensor_divergence needs a square matrix, but got p, which has another shape." The fix passes the pressure as the isotropic tensor p I, whose divergence is (partial(p, 0), partial(p, 1)), the gradient of p.

    TensorSymmetryError

    A tensor state declared symmetric stores only its independent entries, so its rate must have the same symmetry. Here a field of strain on a lattice takes an antisymmetric rate.

    from typing import Annotated

from sage.all__sagemath_symbolics import SR, matrix

from skcomplex.core.components.elements import Element, FieldElement
from skcomplex.core.components.laws import RateLaw
from skcomplex.core.components.spaces import LatticeSpace
from skcomplex.core.components.systems import CompositeSystem
from skcomplex.core.engine.runtime import simulate
from skcomplex.core.errors import TensorSymmetryError
from skcomplex.core.specs import StateSpec


class StrainElement(Element):
    def __init__(self, label, *, S: Annotated[object, StateSpec(tensor='symmetric')] = 0.0):
        super().__init__(label)
        self.S = S

    def _get_laws(self, namespace):
        S = namespace.S
        return [RateLaw(S, matrix(SR, [[0, S[0, 0]], [-S[0, 0], 0]]))]


sheet = FieldElement('sheet', element=StrainElement, space=LatticeSpace((4, 4)))
try:
    simulate(CompositeSystem(elements=[sheet]), until=0.1)
except TensorSymmetryError as error:
    message = str(error)
message.split(' on the tensor state ')[-1]

    sheet.S breaks its symmetry 'symmetric' at the entry [1, 0], by the comparison at random component values, since Sage does not simplify the difference to 0. Give the state a rate of its declared symmetry. [tensor-symmetry]

    The code is tensor-symmetry. The message says that the rate law on the tensor state sheet.S breaks its symmetry 'symmetric' at the entry [1, 0]. The fix writes the rate with the symmetry of the state, here with symmetric_part.

    from skcomplex.core.components.laws.utils import symmetric_part

    def _get_laws(self, namespace):
        S = namespace.S
        return [RateLaw(S, symmetric_part(matrix(SR, [[0, S[0, 0]], [-S[0, 0], 0]])) - S)]


sheet = FieldElement('sheet', element=SymmetricStrainElement, space=LatticeSpace((4, 4)))
simulate(CompositeSystem(elements=[sheet]), until=0.1).get_values('sheet.S').shape

    (11, 16, 3)

    The run records 11 frames of 16 sites with 3 independent entries each.

from skcomplex.core.components.interactions import RateInteraction

try:

except LabelError as error:

message.splitlines()[-1]

    The code is role. The message says that hunting binds the role sources to lynx, which is not an element of the system. The fix adds the element lynx, or binds the role to a label the system holds. A role reaches an element of a nested system by a path such as forest/foxes.

    PipelineError

    A run does not raise this error. The compiler of the library lowers a system through passes, each of which reads some fields of the compilation and writes others. A pass that reads a field no pass writes, two passes that write one field, or passes that read each other in a cycle raise it while the compiler orders them. It concerns those who add a pass to the compiler, and the fix adds the pass that writes the field or splits the cycle.

    InfeasibleError

    A linear program with no feasible point raises this error when its law asks to raise. Two plants of 100 and 50 units cannot meet a demand of 300.

Demand = Annotated[float, ParameterSpec()]

    law_classes = (LinearProgramLaw,)

    def __init__(self, label, *, coal: Output = 0.0, gas: Output = 0.0, demand: Demand = 120.0):
        super().__init__(label)
        self.coal, self.gas, self.demand = coal, gas, demand

    def _get_laws(self, namespace):

        constraints = [coal + gas == namespace.demand, coal <= 100, gas <= 50, coal >= 0, gas >= 0]
        return [LinearProgramLaw([coal, gas], constraints, [LinearObjectiveSpec(20 * coal + 50 * gas, sense='min')])]

message

    The message says that the program of grid has no solution at time 0, names the demand constraint and the variables grid.coal and grid.gas, and suggests infeasible='zero' or infeasible='hold'. The fix is a demand the plants can meet, or one of those policies on LinearProgramLaw.

    EnumerationLimitError

    An exact enumeration that does not finish within its time limit raises this error. The elementary modes of a reaction network, its smallest pathways at steady state, grow in number combinatorially. Here every pair of 14 species exchanges matter in both directions.

    import networkx as nx

def get_exchanges(size):
    arcs = list(nx.complete_graph(size, create_using=nx.DiGraph).edges)
    stoichiometry = np.zeros((size, len(arcs)))
    for column, (tail, head) in enumerate(arcs):
        stoichiometry[tail, column], stoichiometry[head, column] = -1, 1
    return stoichiometry

except EnumerationLimitError as error:
