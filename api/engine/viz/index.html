    AgentsVisual(color_by=None, color_range=None, radius=None, *, position=None, path=None, recording=None)

    Bases: BaseVisual

    Visual that logs the agents of a group as one batch per frame, colored by a state.

    Agents on a grid or in a continuous space are logged as Points2D at their cell centres or positions, and agents on a network as GraphNodes at their nodes, which keep the pos attributes of the nodes, or the positions of a seeded spring layout of the network. On a grid the radius is in cells, and on a network a fraction of the spacing of neighbouring nodes. Without a given radius, agents in a continuous space take a share of the side of the space, smaller for larger groups. Agents in a continuous space are logged with their second coordinate negated, so the view, bounded by the space, draws them with the vertical axis up. Every point carries the agent id as a hidden label, so agents keep their identity across frames and removed agents disappear. Agents whose position is a state are logged at that state: positions of one coordinate, such as cars on a road, as one thin series of one color per agent under <path>/<position>, so their time series view, without a legend, is a space-time diagram, and positions of two coordinates as Points2D with the vertical axis up.

    BaseVisual(*, path=None, recording=None)

    Bases: BaseConfig[BaseProblemSpec, FrameSpec]

    Base class of visuals, which log the state of one element or agent group to a Rerun recording.

    A visual follows the common API of the engine. prepare(problem) finds the element or agent group of the problem at the entity path path, forgets what earlier frames left, and sets the Rerun views that show what the visual logs. run(frame) logs the element at one frame to the recording recording: a compiled element through the hook _log, and agents through the hook _log_agents with the snapshot of the frame. Subclasses implement _log, _log_agents, or both, declare their views with _views, and are named by the kind of a VisualSpec. RerunObserver builds the visual of every element and agent group with their path and its recording.

    Parameters:

    Name Type Description Default
    path str | None

    The entity path of the element or agent group to draw, which also names it in the problem.

    		 None
    recording RecordingStream | None

    The Rerun recording to log to, or None for the active recording of the thread.

    		 None

    Attributes:

    Name Type Description
    element_

    The compiled element or agents the visual logs.
    recording_

    The Rerun recording the visual logs to, or None while no recording is active.
    space_

    The space the agents of the problem live in, or None.
    layouts_

    The positions of the nodes of every network drawn so far, by the id of its graph.
    views_

    The Rerun views that show what the visual logs, each with an entity path of the element as origin.

    Examples:

    >>> from skcomplex.engine.compile import compile_system
>>> from skcomplex.engine.viz import ScalarsVisual

    BodiesVisual(positions, *, pivot=None, rods=False, traced=None, trail=_TRAIL_LENGTH, outline=(), marks=(), radius=None, path=None, recording=None)

    Bases: BaseVisual

    Visual that draws bodies at positions computed from the states of an element, with rods, trails, and outlines.

    The bodies are logged as points under <path>/bodies, the rods from the pivot through the bodies in order as one line strip under <path>/rods, the trails of the traced bodies as segments under <path>/trail that grow more transparent with age, the outlines once as static line strips under <path>/outline, and the marks once as static points under <path>/marks. Every state is also logged as a time series under <path>/<state>. Bodies with three coordinates are drawn in a 3D view. Bodies with two are drawn in a 2D view with the second coordinate negated, since Rerun's 2D views point their vertical axis down, so the views draw it upward.

    Parameters:

    Name Type Description Default
    positions Positions

    A function of the parameters and states of the element by keyword that returns one row (x, y) per body, or the names of the two states that hold the position of a single body.

    		 required
    pivot Sequence[float] | None

    The fixed point the rods start from, or None to start them at the first body.

    		 None
    rods bool

    Whether to draw rods through the bodies.

    		 False
    traced Sequence[int] | None

    The indices of the bodies whose trails are drawn, or None for every body.

    		 None
    trail int | None

    The number of recent positions in a trail, 0 for no trail, or None for the whole path.

    		 _TRAIL_LENGTH

    		 ()

    HistogramVisual(color_by=None, color_range=None, radius=None, *, bins=BINS, shown=('agents', 'mean', 'std'), histogram_first=False, path=None, recording=None)

    Bases: AgentsVisual

    Visual that logs the traits of agents, or the states of a group, without a space as histograms and statistics.

    For every trait of the agents, a number per agent is taken: the value of a numeric trait, the total of a row of numbers such as the ones of a genome, or the size of a collection such as a vocabulary. The visual logs the histogram of these numbers as a BarChart under <path>/<trait>/histogram, over a range that widens to every value logged so far, with one bar per value when the values are few integers, and their mean and standard deviation as series under <path>/<trait>/mean and <path>/<trait>/std. Integer numbers, such as type labels, also log their number of distinct values under <path>/<trait>/distinct, and a group of at most ten agents logs the number of every agent as its own series under <path>/<trait>/agents. Traits of other kinds are left out. The states of the members of a group are logged the same way, one histogram per state.

    ImageVisual(states=None, low=None, high=None, history=None, *, slices=None, moments=None, path=None, recording=None)

    Bases: BaseVisual

    Visual that logs every state of a lattice group as an image colored by value, or a tensor in 3D and more.

    A one-dimensional lattice also logs a space-time image under <path>/space_time/<state>, with one row per logged frame, the oldest at the top, and at most history rows. Its colors span the values of the rows it shows.

    A state on a phase space of more than two axes can log a plane through slices. Its moments over the class axes log under <path>/<state>/moment_<order>, as a bar series over a one-dimensional position lattice and as an image over a two-dimensional one.

    Bases: BaseVisual

    Visual that logs a vector state as points, one per member of a group, and other states as time series.

    Each state is logged as one batch, so a group of any size takes one log call per state and frame. Positions in two dimensions are logged with the second coordinate negated, since Rerun's 2D views point their vertical axis down, so the views draw them with the vertical axis up and show the negated value on hover. Without a given radius, the points take a share of the extent of the positions logged so far, smaller for larger groups. The extent and the count include every element drawn by a points visual of the same position state, so single particles that share a space, such as the masses of a chain, take one radius from the whole drawing.     RerunObserver(application_id='skcomplex', *, spawn=False, connect=False, save_path=None, interval=1, blueprint=None, primary=None, parameters=False)

    Bases: BaseObserver

    Observer that logs frames to Rerun, with entity paths that follow the system tree.

    prepare(problem) creates the recording, builds the visual of every element and agent group from the visual its type declares, lays out their views, and sends the recording to its sinks. run(frame) logs a frame, and run(final=True) flushes the recording. Each logged frame sets the sim_time and step timelines, logs every element with its visual, logs every parameter up to a matrix under parameters/<name>, leaving out coupling tensors, whose entries no view can draw, and logs the renewals of renewal laws since the previous frame as text entries under renewals/<label>. A subclass logs entities of its own apart from the system's with _log_extra.

    The default blueprint puts spatial views first and side by side, with time series views below them. Scalar elements of one type share a time series view with at most six series, and time series views show the whole run. The side panels are collapsed, the top panel is hidden, and the time panel follows the latest frame of the simulated time.

    Parameters:

    Name Type Description Default
    application_id str

    The Rerun application id.

    		 'skcomplex'
    spawn bool

    Whether to spawn the Rerun viewer installed with the running interpreter, or the one on PATH.

    		 False
    connect bool

    Whether to connect to a running Rerun viewer.

    		 False
    save_path str | Path | None

    The path of a .rrd file to save the recording to.

    		 None
    interval int

    The number of frames between logged frames.

    		 1
    blueprint Literal['default'] | Blueprint | None

    The layout of the viewer: None to let the viewer choose it, 'default' for the default blueprint built from the views of the visuals, or a Rerun blueprint. It is sent with the recording, and written next to a saved recording as a .rbl file with the same stem.

    		 None
    primary str | None

    The name or the origin of the view to put first in the default blueprint, with its row, or None for the first spatial view, or the first time series view without one.

    		 None
    parameters bool

    Whether the default blueprint has a time series view of the parameters.

    		 False

    Attributes:

    Name Type Description
    recording_

    The Rerun recording stream.
    visuals_

    The prepared visuals of the elements and the agent groups, in the order they are logged.
    views_

    The views of the visuals, the observables, and the reporters, in the order of the default blueprint, so the first one is the primary view that shows the signature behaviour of the system.
    blueprint_

    The blueprint sent with the recording, or None.
    logged_frames_

    The number of frames logged.

    Examples:
