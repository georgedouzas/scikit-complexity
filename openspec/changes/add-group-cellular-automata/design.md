# Design

## Context

After `redesign-system-model`, a cellular automaton is a `System` under `DiscreteTime()` on a `LatticeSpace`, whose
cells are a `Group(on='sites')` of an element with a categorical state and a `LocalRule` law, and the lattice stepper
lowers the rule to a vectorised stencil over the space's neighbour table. The lattice kind of space declares ordered
neighbourhoods, and the solvers and backends declare their support for it. Rule codes live in
`skcomplex.models.computer_science.automata`. A Cayley graph of a finite quotient is a lattice whose neighbours are
given by right multiplication by the memory set. Sage handles
finitely presented groups, permutation groups, matrix groups, and group algebras through libgap, the GAP library that
`passagemath-gap` ships.

Some groups the books study have no finite presentation. The Grigorchuk group (Ceccherini-Silberstein and Coornaert
2023 sec. 6.9) is generated by `a, b, c, d`, which act on the rooted binary tree by the wreath recursion
`a = (1, 1)(0 1)`, `b = (a, c)`, `c = (a, d)`, `d = (1, b)`. Every element is decided trivial or not by that action,
so the word problem is solvable, but no finite set of relators defines the group. A Cayley ball is then built by
enumerating words and identifying the ones that act alike, not by rewriting with relators.

## Goals / Non-Goals

**Goals:**

- Run any automaton of Ceccherini-Silberstein and Coornaert (2023 ch. 1) whose universe has a computable finite
  quotient or a finite ball, with the same rules and schedules as lattices.
- Decide the properties the book studies wherever they are decidable on finite universes.
- Build group spaces from any finitely generated group whose word problem a mature library solves: automaton groups
  given by Mealy automata, and permutation and matrix groups given by generators, besides finite presentations.

**Non-Goals:**

- Decision procedures for infinite universes, which are undecidable in general beyond dimension one. The checks work
  on periodic configurations over finite quotients and on finite balls, and the documentation states that limit.
- Sofic and surjunctivity theory beyond examples.
- Groups given only by an oracle for the word problem, and growth asymptotics beyond the balls a run builds.

## Decisions

### Group spaces

`GroupSpace(group, quotient=None, ball=None)` lives in `skcomplex.core.space` and takes a group from one of the general
constructors below, or a Sage finitely presented group. Named groups such as `free_group(2)` or `heisenberg()` are
realizations in `skcomplex.models.computer_science.automata`, built on `finitely_presented_group`. With a finite quotient, given as a homomorphism to a permutation group or as a
normal subgroup of finite index, sites are the quotient's elements. With a ball, sites are the words up to the given
length, reduced by Knuth-Bendix or coset enumeration where Sage supports it, and sites on the edge use a fixed fill.
The neighbour table maps each site and memory element `s` to the site `g s`, and becomes the index array of the stencil
lowering.

### Declarations and validation

`GroupSpace` is a space of kind `SpaceKind.LATTICE`: its sites are cells with an ordered neighbourhood, the memory set,
which is what the lattice kind promises, and the Cayley graph of `Z^d` is the square lattice. So `LocalRule`,
`Sample`, and the other laws that require a lattice run on it, and the NumPy and Numba backends that declare lattice
support run it without a new declaration. It declares the options of the lattice kind that it lacks, a regular
geometry and an image layout, and validation reports a law or visual that needs them:
- a `Sample` or rule schedule `'checkerboard'` on a group space is reported as `schedule-unsupported`, whose fix names
  the synchronous and random-sequential schedules, since a Cayley graph need not be bipartite;
- an image visual on a group space is reported as `visual-unsupported`, whose fix names the Cayley graph visual;
- a ball whose radius would exceed the site limit is reported as `space-too-large` with the limit and the size of the
  last ball that fits, before GAP is called.

Groups on edges or hyperedges remain valid only on network spaces, as `redesign-system-model` specifies.

### Groups given by other presentations

A group is given to `GroupSpace` by one of the general constructors in `skcomplex.core.space`:

- `finitely_presented_group(generators, relators)`, the case above.
- `automaton_group(recursion)` takes a Mealy automaton as a wreath recursion, written as the mapping from each state to
  its sections and its permutation of the alphabet, such as
  `{'a': ((None, None), (1, 0)), 'b': (('a', 'c'), None), 'c': (('a', 'd'), None), 'd': ((None, 'b'), None)}`, where
  `None` is the identity. The realization `grigorchuk_group()` of the automata models returns this group with
  generators `a, b, c, d`.
- `permutation_group(generators)` takes permutations as integer arrays of images.
- `matrix_group(generators, ring)` takes square integer matrices and the ring `ZZ` or `GF(p)`.

Balls are built the same way for every kind: a breadth-first search over words of length up to the radius, extended
one generator at a time, which keeps a word only when its element differs from every element already kept. The
equality test is the word problem of the presentation:

- For permutation and matrix groups the element itself is a canonical form, so equality is the comparison of NumPy
  arrays, hashed by their bytes. Integer matrices are checked for overflow of `int64` and raise a named error that
  asks for a smaller radius.
- For automaton groups the adapter hashes each element by its action on the leaves of level `k` of the tree, a
  permutation of `2^k` points that NumPy composes by fancy indexing, and resolves equal hashes with GAP's word problem
  for automaton groups (`IsOne` on `g h^{-1}` in AutomGrp, which uses the contracting nucleus when there is one). So
  GAP is called only on hash collisions, and the result does not depend on `k`.
- For finitely presented groups the existing Knuth-Bendix or coset enumeration path is used.

Sites are numbered by word length and then by the order of discovery, so the ball of radius `r` is a prefix of the ball
of radius `r + 1`. `GroupSpace.ball_sizes()` returns the sizes of the balls up to the radius, which the growth
analysis uses. Automaton groups also give finite quotients: `GroupSpace(group, quotient=level(n))` uses the action on
level `n` of the tree, a permutation group on `2^n` points, so periodic configurations and the theory checks apply to
residually finite automaton groups as they do to finite quotients of presented groups.

Computed with two independent methods, the level-14 tree action and the recursive contraction algorithm, the balls
of the Grigorchuk group for the generators `{a, b, c, d}` have sizes 1, 5, 11, 23, 40, 68, 108, 176, 271, 427, 643 for
radii 0 to 10 (spheres 4, 6, 12, 17, 28, 40, 68, 95, 156, 216), and its level quotients have orders 2, 8, 128, 4096,
`2^22` for levels 1 to 5, matching `2^(5 * 2^(n - 3) + 2)` for `n >= 3`. The sequence 1, 5, 11, 23, 43, 79 sometimes
quoted for the radii 0 to 5 does not match either computation and is not used.

GAP is the reference system for computational group theory and the only maintained library with automaton groups, so
the change wraps it instead of reimplementing the word problem. Because GAP, FR, and the Sage group wrappers are GPL,
they go in the optional extra `groups = ["passagemath-groups>=10.8.13", "passagemath-gap>=10.8.13"]`, imported lazily
inside the group constructors with a suppression whose reason names the extra. Without the extra a constructor raises
an `ImportError` whose message says `pip install scikit-complexity[groups]`. The extra holds the finitely presented
groups of the decision above as well, because Sage's finitely presented groups also come from libgap.

### Fit with the framework

GAP only builds the space. `GroupSpace` stores the neighbour table as an `int64` array of shape `(sites, memory)`,
with `-1` for neighbours outside a ball, so the stencil lowering, the NumPy and Numba backends, the schedules, and the
compile pipeline of Sage laws lowered to NumPy and Numba run unchanged, and running a rule never calls GAP. The time
axis is the automaton's step, as on lattices, and `run` returns a trajectory of cell states per site; the ball sizes
are a property of the space, not of the run. Rerun shows a group space as graph nodes and edges, one node per site and
one edge per generator, laid out once with sites on rings by word length, and node colours follow the cell states at
each step.

### Grigorchuk model

`grigorchuk_automaton` registers under `computer_science/automata` with the sources of its inventory entry (CC 6.9).
It is a `System` under `DiscreteTime()` whose space is a `GroupSpace` of the library's `grigorchuk_group()`, and whose
cells are a site group with a `LocalRule` majority law. It runs the majority automaton with the memory set
`{1, a, b, c, d}` on a ball of radius 8, 271 sites, from a random configuration with a fixed seed and a fixed fill
outside the ball. Its catalog entry declares the cell states and the density of ones as observables. The other group
automata models are built the same way from the named groups of the automata package. Its gallery example streams the Cayley ball to
Rerun with node colours by state, which is the thumbnail, and plots the ball sizes for radii 0 to 10 from
`ball_sizes()` on logarithmic axes, against the exponential `5^n` and the free group's `1 + 2 (3^n - 1)`, to show
growth that is faster than any polynomial and slower than any exponential: the local log-log slope rises while
`log |B(n)| / n` falls.

### Theory checks

On a finite quotient, injectivity and surjectivity of the induced map on configurations are decided by enumeration
for small alphabets and sizes, and by a SAT encoding with PySAT otherwise. Pre-injectivity is checked on pairs of
configurations that differ inside a finite window. Garden of Eden patterns are searched as unsatisfiable preimage
constraints over a window, and `inverse` searches for a local rule with a memory set up to a given size whose
composition is the identity.

### Linear automata

`LinearAutomaton(group, field, coefficients)`, in `skcomplex.core.analysis.automata`, represents `Σ a_s s` in the group algebra `K[G]`. Invertibility,
surjectivity, and pre-injectivity follow from the algebra on finite quotients and, for `Z^d`, from Laurent polynomial
arithmetic over the field.

### Subshifts

`Subshift(alphabet, forbidden_patterns)` lives in `skcomplex.core.analysis.automata` with the theory checks, since it
describes a set of configurations rather than a law of a system. It checks configurations, counts admissible patterns in windows, and samples
admissible configurations by Markov chain moves that respect the constraints.

### Information

`configuration_entropy(subshift or automaton image, windows)` estimates `log |X_F| / |F|` along a Følner sequence of
windows. `difference_pattern(automaton, configuration, site)` returns the space-time set where two runs differ after a
single-cell flip, as Lindgren (2024 ch. 4) uses.

## Risks / Trade-offs

- [Exponential checks] → Enumeration has size limits that raise a named error, and SAT encodings extend them.
- [Knuth-Bendix may not terminate] → Balls require a group with a solvable word problem in Sage, otherwise a named
  error asks for a finite quotient.
- [Copyleft dependency] → GAP and the Sage group wrappers are GPL-2.0-or-later, so they live in the optional `groups`
  extra and are imported lazily, and the default install gains no package. The core `passagemath-symbolics`
  dependency is also GPL-2.0-or-later, an existing exception this change does not widen.
- [Exponential balls] → Ball sizes grow fast even for groups of intermediate growth, so `GroupSpace` raises a named
  error above a site limit, 100000 by default, before calling GAP.
- [GAP start-up time] → libgap starts once per process, and the adapter computes a whole ball in one GAP session, so
  the cost falls on space construction, not on steps.
